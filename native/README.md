# Pluton native

Native iOS + Android apps with **one shared core**: Kotlin Multiplatform for the learning rules, Jetpack Compose
on Android, SwiftUI on iOS. The point is to implement FSRS, grading, the run queue and prompts once, not twice.
Everything is local: there are no accounts and no server.

Learning-design research and the prioritised feature roadmap: [LEARNING.md](LEARNING.md).

```
native/
  shared/       Kotlin Multiplatform core (grading, tokenizer, FSRS, run queue, SQLite store)
  androidApp/   Jetpack Compose app
  iosApp/       SwiftUI app (consumes the shared framework; built by the macOS CI workflow)
```

## Build Android (this machine)

```bash
JAVA_HOME=/home/moloch/.local/opt/jdk-21.0.12.1+1 ANDROID_HOME=/home/moloch/Android \
  ./gradlew :androidApp:assembleDebug
# apk: androidApp/build/outputs/apk/debug/androidApp-debug.apk
```

The native app uses the same `applicationId` as the Capacitor app, so installing it over the old debug APK replaces
it; the native app starts with empty storage (IndexedDB data does not migrate). Uninstall the old app first if you
want to keep both sides' data around for comparison.

## Run on an emulator

KVM is available on this machine. One-time setup:

```bash
export ANDROID_HOME=/home/moloch/Android
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "emulator" "system-images;android-36;default;x86_64"
echo no | "$ANDROID_HOME/cmdline-tools/latest/bin/avdmanager" create avd -n pluton \
  -k "system-images;android-36;default;x86_64" -d pixel_6 --force
```

Then:

```bash
"$ANDROID_HOME/emulator/emulator" -avd pluton -no-window -no-audio -no-boot-anim -gpu swiftshader_indirect &
"$ANDROID_HOME/platform-tools/adb" wait-for-device
"$ANDROID_HOME/platform-tools/adb" install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk
"$ANDROID_HOME/platform-tools/adb" shell am start -n io.github.vykosmolt.pluton/.MainActivity
"$ANDROID_HOME/platform-tools/adb" exec-out screencap -p > /tmp/pluton-native.png
```

The first boot takes a couple of minutes; the app spends a few seconds decoding the 20k words. Progress is saved
in SQLite (`pluton.db`), so closing the process keeps the cards and the review log. On this machine the API 36
system-image download stalled, so the APK has still not been launched; the commands above are the intended path.

The FSRS parity test is generated from the web app's `ts-fsrs`; after changing scheduler fixtures or the library:

```bash

```

Toolchain: Gradle 8.14.4 (Kotlin 2.4.21 needs >= 8.14.4), Kotlin 2.4.21, AGP 8.13.0, compileSdk 36, Compose BOM
2026.03.01. The 2026.09 BOM requires AGP 9.1 + compileSdk 37; don't upgrade until the native apps need it.

## iOS

`iosApp/` is a SwiftUI app generated by XcodeGen from `project.yml`; it consumes the shared core through
`PlutonCore.framework` and has a Swift-friendly facade (`IosBridge`, `IosRun`) in `shared/src/iosMain`. It covers
Home/run, Read (library, coverage, tap-to-look-up, quiz, user texts, TTS, Norman Bridge), Listen (local audio/video,
subtitles, line controls, dictogloss), Speak (TTS, record/playback, speech recognition, Talk), and More (Path, Words,
Verbs, Grammar, Settings with a Keychain-stored BYOK key). Progress lives in the app's SQLite store; nothing is sent anywhere except the AI provider you configure.

The iOS targets are registered only when Gradle runs on macOS, because Kotlin/Native needs Xcode. On a Mac:

```bash
brew install xcodegen
cd iosApp && xcodegen generate && open Pluton.xcodeproj
# or exercise the framework directly:
./gradlew :shared:linkDebugFrameworkIosSimulatorArm64
./gradlew :shared:embedAndSignAppleFrameworkForXcode
```

A simulator build needs Xcode, not a paid account; device/store builds need the Apple Developer Program.
**The Swift sources cannot be compiled on this Linux machine.** The GitHub Actions workflow builds the unsigned IPA
and installs/launches it in a simulator on macOS; the run for `cc6dda09` was green. The Listen tab is the first
change that run did not compile. See `iosApp/README.md` for the feature list, build prerequisites and known gaps
(no story generator/retell, word-only runs).

## Status

Reader v1 + read-along + classics + user texts + Listen + Speak + AI Talk + reference (2026-10-21): the shared core has the tokenizer/coverage/unlock,
sentence extraction, run queue + requeue, FSRS-6 scheduler with parity fixtures from `ts-fsrs`, word/forms/story/
shelf decoding, `gradeDictee`, and a SQLDelight store (`cards`, append-only `reviews`, `meta` stats with
read/listening/spoken history). The Android app has Home / Read / Listen / Speak / More tabs, loads the real 20k-word deck and saved
cards, plays a run with the web app's exercise cycle (cloze → dictation → recall from English with the right
article → full-sentence dictée), reads Pluton's 10 story chapters, the 7 French classics and any text you paste in
(coloured by word status, tappable for gloss/add/known, queue-to-unlock, comprehension quiz for the story, sentence
audio with highlighting), and practises speaking with French TTS, MediaRecorder record/playback, and Android speech
recognition with word-level dictation marks and a recognizer-match percentage (`dicteeScore`: full credit per word
heard, 0.7 for accent slips; explicitly not phoneme scoring). User texts live in the SQLite `texts` table (schema v4)
and can be deleted or read aloud by the device voice; they have no quiz. The Listen tab plays a local audio/video file
chosen with the system picker alongside an `.srt`/`.vtt` file (`parseCues`/`cueAt` ported to the shared core), shows
the current line coloured by word status with tap-to-look-up, and has line prev/replay/next, pause-after-each-line and
0.75–1.25× speed for audio. Video files render in a `VideoView` with the same subtitle/line controls; speed control is
audio-only (the platform VideoView doesn't expose its player).
The More tab shows Le Chemin (the ten-stage A1→C1 path from `src/lib/path.js`, with per-goal progress and the current
stage also on Home), the deck browser (every saved word newest first, searchable by French or English, filterable by
status, with memory strength, next-review time and word audio on tap), all 59 conjugation tables (6 tenses each,
cell audio for the 2,063 recorded forms) and the 15 grammar topics with revealable exercises. "Practice" adds a card; runs then ask either a conjugation cell (typed,
pronoun optional, être-verb agreement not tested) or a grammar gap, with the same FSRS scheduling and review log as
words. New tables/topics also enter runs automatically once their verb/topic prerequisites graduate. Word cards use
`modeFor` (cloze, listen-and-type, English→French recall with article/gender grading, full-sentence dictée with
word-level marks); dictation plays the sentence clip on arrival and every exercise has a replay button. More→Settings
has the new-word pace (per run/per day, persisted), JSON backup/restore through the system file picker (replace-all,
transactional, no keys included) and the licences, plus the AI tutor configuration. The Speak tab has three modes:
read-aloud practice, **Talk with Pluton**, a BYOK chat that reuses the shared `chatSystem` prompt and the learner's
level/vocabulary, counts messages as talking, and formats Pluton's correction line; and **Write**, which offers
level-appropriate prompts, sends `writeSystem` to the model, parses the corrected JSON (`parseWriting` tolerates prose
or code fences), and shows the corrected text, each original→fix with its explanation, the feedback and an estimated
level. Corrections count as writing for Le Chemin. In the reader, **Story** generates a 150–250-word story at the
learner's level from `readerSystem` (known words recycled, learning words woven in) and saves it to Your texts; the
reading view for classics and your own texts has an AI **retell** check (`RETELL`, effort medium) that scores
comprehension 1–5 and explains what was missed — story chapters keep their written comprehension quiz instead.
The reader's **Norman Bridge** section lists the five English shelf texts (Poe, Lovecraft) and marks every word
English inherited from French, with false friends in red. Tapping a word explains the link, and the weave modes
rewrite the English in French wherever you already know the counterpart, so the text turns back into French as your
deck grows.
Your texts and generated stories have no recorded clips, so their Listen button reads them sentence by sentence with
the device's French TTS voice (`sentencesOf` mirrors the web's splitter) and highlights the line being spoken.
Claude goes through the official Anthropic Java SDK
(`claude-opus-5-5`, low effort, non-streaming); OpenAI, DeepSeek, OpenRouter, Ollama and any OpenAI-compatible
server use the chat-completions HTTP format. The key is stored only in this app's private prefs, Android backup is
disabled, and it is excluded from the JSON backup. Talk transcripts are in memory for the session; writing drafts and
corrected texts are saved locally, and revisions keep their record id across restarts. Progress, read history, listening seconds, spoken attempts, talked messages, writing corrections and user
texts survive restarts.

**Local only.** There is no account, no sign-in and no sync server. Cards, the review log, texts, stats and pace
live in the app's SQLite database; the AI key lives in private prefs (Android backup disabled) or the iOS Keychain
and is excluded from the JSON backup. Speech recognition and text-to-speech are platform services (on-device or
system-provided, depending on the device); only the recognized transcript is sent to the AI. The only network calls are the AI requests you trigger (and the media files
you pick in Listen are read locally). The shared `Sync.kt` merge rules remain for reference but nothing in either
app wires them up. 122 shared JVM tests and 28 Android JVM tests pass (5 AI, 23 Robolectric UI). The APK is 55 MB with 3,053 bundled clips (story, classics and conjugation); the Claude SDK adds ~9 MB and needs
core-library desugaring for `java.time` on minSdk 24.
`AppLaunchTest` launches the real Activity under Robolectric on the JVM and verifies the deck/shelf assets, SQLite,
Home (with the path stage), all five tabs, the story + classics list, the Your texts section, the Listen pickers, the
conjugation/grammar reference, the path screen, the deck browser, Settings with the AI section,
the Talk/Write no-key states, the story-generator panel, the retell no-key state on classics (and its absence on story
chapters), and adding a user text with its Listen button; a physical
device/emulator is still untested (the API 36 image download stalled), so the file picker, TTS, recording, speech
recognition, and audio playback have not run on-screen.

Data prerequisite: `uv run data/fr/build.py` must have produced the JSON files under `public/data/fr/` (words,
forms, story, shelf, conj, grammar, cognates); the Gradle `syncData` task copies them into assets at build time and
fails with a clear message if they are missing.

The P0 learning loop is in place: a one-question onboarding sets the daily time and pace; Home opens with a four-step
Today card (review, read, speak, write), a gentle weekly consistency row, and lets the learner tick each step; the pace suggestion uses the share of Good/Easy
answers in the last 30 reviews; the last tab returns on launch; reading cards label coverage as comfortable (98%+),
stretch (95–98%) or challenge (<95%) and the queue action targets 98%; Le Chemin has separate Talk and Speak bonus goals;
writing is saved locally with its errors, a revision flow and an error summary; both platforms have a Write tab (iOS
previously had none). SQLDelight schema v4 adds `writing` and `corrections`; backups include both (version 3 also carries can-do
ticks and correction schedules), and both platforms now have an export/import UI.

P1 adds the speaking loop: Talk has a microphone (Android SpeechRecognizer / iOS SFSpeechRecognizer), sends the transcript to the AI and can speak the reply with French TTS; Speak also has a **Fluency** mode (shadowing, plus 4/3/2 with a countdown and recording) and a **Sounds** mode (nine curated lessons: nasals, /y/–/u/, /ʁ/, /s/–/z/, /ʃ/–/ʒ/, final consonants, liaison, silent letters, e caduc) with a minimal-pair quiz, phrase playback and recording. The Android manifest already had RECORD_AUDIO; iOS already had the microphone/speech usage strings. No new server, no new account, no new permission beyond the existing microphone.

P2 starts the depth pass: 24 curated French chunks (il y a, avoir besoin de, tout à coup, …) become normal SRS cards from the word sheet, with synthetic `chunk:` lemmas and cloze-only reviews; mined words alternate between the sentence they were tapped in and their dictionary sentence, with the matching inflected form; grammar/conjugation focus is computed from the learner's current card state and passed into Talk, Write and a reading notice; Android Listen has a dictogloss (type the line you hear, word-level feedback); and “Continue this text” asks the AI for a 150–250-word continuation and saves it as a new local text. iOS has chunks, context alternation, focus prompts, reading notices, continuation and the Listen tab (audio/video, subtitles, line controls, dictogloss).

P3 completes assessment and polish: More→Progress shows a broad receptive vocabulary estimate (A1–C1 range,
explicitly not a test), last-30-review accuracy, a Last 7 days card (review count and Good/Easy rate), a can-do
self-assessment for the current stage (saved locally) with a checkpoint line, a Cabinet of finished story chapters,
classics, Bridge texts and user texts, and milestones for words, reading, classics, Bridge texts, listening hours,
recordings, AI talk and corrected writing. The same screen is in iOS More.

P4 closes the writing loop: More → Error review turns the corrections from Write into short retrieval drills. It
shows the fragment or sentence you actually wrote, you type the fix, and it grades exact / accent, capital or typo / wrong, then shows
the correction, the reason and the error kind. The shared `errorDrills` de-duplicates by normalised pair and keeps
the newest 20; `gradeError` reuses the existing grading rules. No new storage or network path: it reads the
corrections already in SQLite.

P5 spaces the error loop: schema v5 adds `next_due`/`reps` to corrections. Error review shows only drills that
are due now. A correct answer moves the next review 1 → 3 → 7 → 16 → 35 days out; "almost" comes back
tomorrow; wrong resets it to now; six correct reviews retire a correction. The More entry counts due drills, and
backups carry the schedule.
